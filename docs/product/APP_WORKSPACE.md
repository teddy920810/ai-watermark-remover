# App workspace and staged operation adapters

Status: current implementation contract. The [refactor ledger](./REFACTOR_LEDGER.md) records PR98's 2026-11-01 deployment, real OAuth and six-operation acceptance; [release records](./RELEASE_READINESS.md) distinguish later video, download and payment changes. Each new change requires its own applicable verification; historical results do not pass a new release gate.

`/app` renders the product entry. `/app/image` and `/app/video` use the same `AppWorkspaceLayout`, `AppWorkspace` and `AppShell`; they remain compatible draft/task links. Static HTML contains only public branding/copy and a readable loading/reload/no-JavaScript explanation. Private files, balances, quotes and tasks are loaded after authentication. The interactive workspace loads as a chunk and a failed load leaves a reload action.

`AppShell` owns navigation, account presentation, operation selection and the layout. `WatermarkWorkspace` retains one durable coordinator for all six operations. `ObjectMaskEditor` keeps object-specific selection policy separate from refinement; `BackgroundOptions` keeps local color compositing. Vendor requests, price consent, server ownership and financial settlement retain their operation contracts. Refinement remains an action on a supported completed result; an arbitrary original cannot request refinement through a query parameter.

Local file, draft, preview URL and metadata form one snapshot. Preparation has idle/working/failed phases; quotes have idle/preparing/quoted/submitting/uncertain/failed phases in `workspace-flow-state.ts`. Submission and uncertain recovery retain the original quote, while the synchronous submit lock and quote/key/scope ref still prevent duplicate or stale requests. Generation and owner guards remain responsible for asynchronous response isolation. This is local state consolidation: API payloads, session recovery records, CMS schemas and financial rules require no migration.

| State | Action and transition | Invariant |
| --- | --- | --- |
| Loading or chunk failure | Explain/reload the same URL | No private data in the static shell; reload does not create a processing request |
| Anonymous local file | Preview the file, choose a compatible operation, sign in | Local draft only; intake does not upload or charge |
| Initial sign-in | Keep the mounted editor and its explicitly accepted state | A session refresh must not discard the original file or selection; unquoted sign-in is not processing consent |
| Authenticated durable preparation | Restore/upload/inspect the same owned source and selection | Non-billable preparation; late file/selection/account responses cannot replace current state |
| Valid durable quote | Show amount, unit, balance and output, then require the processing button | File/operation/selection/expiry changes invalidate the quote; wallet phase determines the unit and legacy balances remain distinct |
| Unconfirmed durable submission | Check the original quote and key | Do not replace its key or create a fresh paid replay |
| Accepted durable task | Restore its deep link or Recent work; refresh status | The accepted task determines media type ahead of a new operation hint; CAS/lease/outbox/unknown/late-result rules stay server-owned |
| Completed durable result | Compare/download real bytes and use supported refinement/versions | Original result/session/PRO constraints and artifact metadata remain intact |
| Durable background | Prepare/quote in the common coordinator, then require explicit confirmation | Preserve original-size transparent PNG and local color-composited PNG; legacy accounts use free/purchased image balances, unified accounts use Credits |
| Durable object | Bind source/mask to the current quote and confirm explicitly | Preserve brush/lasso/eraser, twenty snapshots and opaque binary masks; original-size PNG and the current wallet's quoted unit |
| Account change | Unmount private state, clear App pointers and restore only eligible drafts | Authenticated drafts carry an owner; another owner or anonymous state cannot restore them |

Unowned drafts remain anonymous handoffs for compatibility and can be claimed on initial sign-in. The claim preserves the file and its identifier rather than replacing a mounted editor. Account metadata in IndexedDB is a UI isolation rule, not a security boundary; every private upload/task/download is still authorized by the server. Existing ownerless records cannot retroactively establish an earlier identity and retain their original one-hour expiry.

Image-operation switches retain the current source in the mounted coordinator and invalidate the old quote/selection. Accepted and UNKNOWN tasks remain locked to their original identity. A media-type switch saves the original local handoff, or reopens the current owner's original artifact before navigation; failure keeps the current state and reports an error. The local third batch removes the old upload and JobService routes after the owner confirmed there are no real production users. Current v1 tasks retain their original quote, key, ownership and recovery rules; no database or R2 records are deleted.

The operation selector owns Standard/PRO selection; its explanatory text follows the account's wallet phase. Current operation actions and output labels are code-owned. CMS can supply public content copy but cannot choose the upload API, Provider, operation implementation or price.

Wallet units, source rules, rates and account migration follow the [Credits contract](../PROCESSING_CREDITS.md). Legacy video quotes use `processingCredits`; unified accounts use `credits`. File checks use no credits; the processing button shows the server quote and requires an explicit click before reservation. An insufficient balance cannot be replaced with another legacy unit. This shared workspace does not convert accounts or merge legacy balances.

Download tickets carry the filename selected by `PublicProcessingProjection`: Standard, PRO and refinement use `cleaned-image.jpg`; background uses `background-removed-image.png`; object uses `object-removed-image.png`; video uses `cleaned-video.mp4`. The private R2 signer supplies the same name in `Content-Disposition: attachment`, and the workspace sets the anchor's `download` name. Cross-origin downloads depend on the final R2 response header, so an anchor attribute alone is insufficient evidence. Local color compositing exports `background-removed-image.png` as PNG without creating another processing task. Each download requests a fresh ticket; an expired stored artifact remains unavailable and must not trigger automatic reprocessing.

`tests/e2e/download-filenames.spec.ts` checks all six restored results and local white-background export on desktop and mobile viewports. It passes the real public projection through the real SDK signer to a separate HTTP fixture origin, checks `suggestedFilename()` before reading bytes, refreshes tickets, and rejects processing mutations. It also checks the actual on-disk filename using normal filename behavior in an isolated browser context. This is local browser evidence; real R2 headers and authenticated production button downloads need separate checks against retained artifacts. Renaming a test output with `saveAs('result.jpg')` does not establish the browser's natural filename.

A UUID without an extension can be an automation artifact even when the response and suggested filename are correct: Chrome's [`allowAndName` download behavior](https://chromedevtools.github.io/devtools-protocol/tot/Browser/#method-setDownloadBehavior), used by Playwright's accepted downloads, stores files under their download GUIDs. Record the suggested filename and the ordinary on-disk save separately. Do not change production downloads to compensate for a browser automation override, or silently change the user's browser settings. A preview image's native Save As path is separate from the download button and may suggest its artifact ID. A system hiding known extensions is also a separate display setting; inspect the actual file name before attributing that symptom to the product.

`design-system.css` owns shared primitives. `workspace.css` and `image-editor.css` own App/editor presentation. Image output and object-selection controls use the `.workspace-image-options` scope. Their image and canvas planes preserve the source aspect ratio, including portrait images; an inherited height cap must not stretch the mask independently of the displayed source. Public pages hand files to App. Zero-consumer legacy editors, their old price/read helpers and synthetic comparison components are retired; the old processing APIs and historical deployed-chunk carry-forward implementation are retired locally. `MediaLauncher` and its styles select both Web targets. [File intake](./FILE_INTAKE.md) describes replacement/drop and recommendation policy.

Google sign-in retains the existing initializer object and callback behavior. Primary vendor reference: [Better Auth Google](https://better-auth.com/docs/authentication/google). Browser fixtures simulate session completion and verify price/file retention; they do not confirm a real OAuth flow. PR98's real OAuth and processing evidence is recorded separately in the refactor ledger. New authenticated processing smoke requires the applicable deployment and an explicit remaining paid-operation budget; previous call slots are not renewed by a later task.
