## 1. 当前事实与产品判断

采购的 Dewatermark API 同时提供图片和视频去水印。图片可以自动处理、使用 PRO 模型，并通过会话和画笔遮罩继续精修。视频采用上传、提交、轮询、下载的异步流程，支持一个覆盖整段视频的静态选区。[官方 API 参考](https://dewatermark.ai/api-document)

本项目已存在 Dewatermark v3 图片自动处理适配，可由服务端配置启用。调研基线尚无 PRO、画笔精修和真实视频处理链路。现有实现增加了这三项，是否已上线仍须逐项通过实施清单中的发布门禁。产品设计应延续已有上传、登录和私有文件存储，同时为视频补足任务恢复、成本确认和结果保存。

建议采用一套品牌、两个工作区：图片强调对比与精修，视频强调范围确认与后台任务。首期单文件处理；批量、动态水印追踪、分段选区、自动转码、免费结果试片不进入首期承诺。

## 2. API 能力与边界

| 项目 | 已确认的文档能力 | 设计边界 |
| --- | --- | --- |
| 图片自动 | `POST /api/object_removal/v3/erase_watermark`；默认模型 4.0；普通调用每次 1 个供应商积分 | 选择文件不触发处理，必须明确提交 |
| 图片输入 | 请求表要求 JPEG，最长边不超过 6000px | 本站接收 PNG/WebP 后需转换；不承诺透明通道、无损和原文件格式 |
| 图片精修 | 可传 `session_id`、`mask_brush`、`mask_base`，返回图像和遮罩 | 每次提交精修都属于新的处理操作；涂抹、撤销不调用 API |
| 文字移除 | `remove_text=true` 可能移除所有文字 | 默认关闭；首期不暴露“移除所有文字”快捷开关，避免误伤商品文字 |
| PRO | `POST /api/object_removal/v1/erase_watermark_pro`，每次 3 个供应商积分 | 标为“高质量模式”，不是放大分辨率；普通与 PRO 二选一，不自动升级 |
| 视频输入 | MP4、24fps、最长 9 分钟 | 首期不静默转换不兼容文件；视频体积、编码、分辨率上限待核实 |
| 视频选区 | 可选 PNG 遮罩，与视频画面同尺寸 | 首期为固定区域、整段生效；时间轴只供检查，不表示关键帧或跟踪 |
| 视频任务 | 申请上传地址 → PUT 文件 → 提交 task_id → 轮询 | 上传完整后才能提交；保存 task_id，刷新继续查询 |
| 视频进度 | CREATED / PROCESSING / COMPLETED / FAILED，progress 0–1 | 区分本站提交阶段与供应商状态；不伪造处理百分比和预计完成时间 |
| 视频结果 | 下载签名地址有效 2 天 | 服务端取回并存入本站私有 R2 后才标记可下载 |
| 视频成本 | 0.5 个供应商积分/秒；文档称失败和超时退款 | 按该值保守估算成本；小数时长、进位及实际扣费点待确认 |
| 账户 | 有只读余额查询接口 | 供应商余额用于后台可用性控制，不作为用户余额显示 |

以上事实来自[API 参考](https://dewatermark.ai/api-document)，不等于本账户已开通所有能力或已通过质量测试。

### 文档冲突与未公开项

1. 图片请求主表写最长边 6000px，精修说明又写前次结果不超过 1920px；不能承诺精修保持高清尺寸。
2. `mask_base` 表格写文本，示例却上传文件；会话替代原图的说明与同时传两者的示例并存。二值遮罩的当前 v3 黑白语义也需验证。
3. PRO 示例虽有 `session_id`，但没有承诺它能继续调用普通 v3 精修。未验证前，PRO 结果仅设计对比、下载和新建处理。
4. [API 营销页](https://dewatermark.ai/watermark-remover-api)及[接入文章](https://dewatermark.ai/blog/how-to-integrate-dewatermark-api)的视频价格为约 0.2 积分/秒，与 API 参考的 0.5 不同；文章还使用旧 v2。结算以采购约定、供应商书面确认及账户实扣为准。
5. [视频网页](https://dewatermark.ai/video-watermark-remover)的免费 5 秒试片、时长和音轨宣传不是 API 合同；API 没有公开预览、裁剪、取消、关键帧、Webhook、幂等或断点续传契约。
6. 图片失败退款、会话有效期、视频最大体积/分辨率/编码、并发/限流、超时阈值、无水印任务计费、结果音轨和色彩保持均未完成验证。
7. [隐私政策](https://dewatermark.ai/policy)、[首页](https://dewatermark.ai/)与视频结果期限的表述不同；[条款](https://dewatermark.ai/term-of-service)包含运营或改进服务的内容许可。本次不作法律结论；API 专属留存、删除、训练用途和白标权限应获得书面确认，产品文案不能自行写成即时删除或绝不训练。

## 4. 入口与共同交互

图片和视频各保留自己的工具落地页，进入工作区后可切换类型。切换时若有未提交选区，提示“保留当前编辑，还是更换文件”；已提交任务继续后台执行。公共 Header 和其他工具的流程保持既有规则。

工作区只突出一个当前操作。顺序为：本地选择与预览 → 编辑模式或区域 → 登录 → 上传并完成服务端检查 → 确认费用 → 提交 → 对比与下载。登录只保存身份，不代表同意发起处理。

上传前读取可在本地确认的大小、尺寸和时长；视频帧率、编码等由服务端媒体检查确认，不能仅依赖浏览器提供的元数据。这里先上传到本站 R2，尚不创建供应商处理任务。用户看到报价后再开始；文件、模式或时长改变，报价随之失效并要求重新确认。视频确认后才由服务端申请供应商 task_id、向供应商完整上传、提交开始处理，再轮询状态；两段上传必须在状态文案中区分。

### 4.1 落地页初始状态：未选择文件

首次访问必须回答三个问题：处理什么文件、从哪里开始、何时产生费用。图片和视频有各自的标题、示例、限制、操作说明与 FAQ，沿用既有 Header、Logo、蓝白配色和字体。图片类细分工具可共享结构，但不能共用与当前用途无关的示例或 FAQ。

| 首屏元素 | 图片落地页 | 视频落地页 |
| --- | --- | --- |
| 页面身份 | 图片去水印；英文主文案 `Remove watermarks from images` | 视频去水印；英文主文案 `Remove watermarks from videos` |
| 一句说明 | 上传图片，检查结果，按需精修剩余水印；精修实际开放仍受契约验证门控 | 适合固定位置水印，选择视频后设置自动检测或固定区域 |
| 主按钮 | 上传图片 / `Upload image` | 服务启用后为上传视频 / `Upload video` |
| 紧邻限制 | JPG / PNG / WebP，最大 10MB；输出为 JPG | MP4、24fps、最长 9 分钟；体积上限核实后再显示 |
| 费用提示 | 上传不开始处理，开始前确认费用 | 同左；不将供应商积分直接作为本站售价 |
| 辅助操作 | 先看示例，少量示例缩略图 | 先看示例视频，明显播放按钮与演示标识 |
| 效果说明 | 示例前后对比；概念媒体标注为示意 | 固定角标的演示视频；不得暗示支持动态追踪 |
| 此时不显示 | 画笔、模型设置、版本列表、虚构任务或成功状态 | 关键帧、编辑时间轴、任务进度、取消退款或虚构历史 |

桌面图片页延续“示例媒体 + 上传区”的两栏结构。视频页可突出居中的空上传区，把示例放在上传操作之后；主入口在首屏可见。主 CTA 始终只有一个，不让下载、精修或无关注册动作抢占重点。

手机顺序为 Header → 简短标题与说明 → 上传按钮 → 格式/输出/费用说明 → 示例。以 390×844 为设计检查视口，要求无需滚动就能发现主上传入口。大幅示例不能排在上传前面；拖放提示不是手机必需操作。图片与视频手机页使用同一层级，视频替换为自己的格式限制和演示。

首屏下方按需放置三步操作说明、具体能力与限制、独立 FAQ 和重复上传入口。重复入口触发同一个文件选择和业务流程。初始页不展示未经确认的“100% 免费”“无损”“瞬间完成”“免费 5 秒试片”、虚构用户数或效果保证。当前 SEO/页面记录中如有这些旧表述，后续实现时需与能力、费用和 CMS 内容一起对齐；本轮不修改。

### 4.2 初始状态的交互与恢复

| 状态或事件 | 页面反馈 | 下一步 |
| --- | --- | --- |
| 匿名首次进入 | 可选择文件、查看本地预览或打开示例；不先弹登录墙 | 到本站上传与报价所需阶段再登录 |
| 已登录首次进入 | 主上传入口不变；仅有真实短期任务时才显示继续入口 | 不生成虚构空历史或空余额卡片 |
| 打开后取消文件选择 | 保持原页面与当前文件状态 | 允许再次选择 |
| 文件拖入 | 上传区边界和文案变为“松开以选择”，同时提供可见状态文字 | 松开后先本地检查，不直接处理 |
| 拖入多个文件 | 就地提示“当前一次处理一个文件” | 用户重新选择；不静默取第一份 |
| 格式、体积或文件读取错误 | 上传区附近说明具体原因和允许值，重新选择按钮仍可用 | 修正后移除错误，不清空无关设置 |
| 视频兼容性尚未确认 | 显示检查文件；浏览器能播不等于 API 兼容 | 后续服务端确认帧率、编码、完整性和时长 |
| 匿名选好文件 | 保留文件、预览与模式 | 登录后回到既有设置和报价流程，不自动收费 |
| 视频尚未开放或临时不可用 | 显示明确准备中/暂不可用状态；不接受真实视频上传 | 可看演示；不回落到图片上传器，不虚构排队任务 |
| 切换图片/视频入口 | 无未提交编辑时直接切换；已有文件或选区时明确询问保留还是更换 | 已提交任务继续后台执行 |

有效文件选中后，上传区转为文件预览和下一步设置，保持原页面身份及返回入口。焦点移到文件信息或下一步按钮，并向辅助技术播报状态。返回初始页与更换文件应有独立含义，不因浏览器后退丢失已提交任务。

示例为独立演示模式：无需登录，不调用真实处理 API，不消耗采购额度。可对比、缩放或播放预先制作的媒体，主行动变为“上传自己的图片/视频”。示例不伪装成一次真实处理，不显示虚假进度或任务成功通知。若允许下载，需清楚说明下载的是示例文件。用于上线宣传的前后效果应来自有权处理且实际验证的媒体；本轮生成图只作为概念说明。

上传按钮及辅助动作触控范围至少 44px；不能仅靠颜色说明可拖入或发生错误。错误内容与输入关联，键盘可打开文件选择与示例。首屏隐私表述限于本站能执行的私有存储和临时保留规则，不替供应商承诺即时删除。

### 4.3 初始状态验收

1. 图片和视频页面一眼可分，选择器接受各自媒体；视频服务关闭时不会误进图片流程。
2. 390×844 手机视口及代表桌面视口都能找到上传入口，格式和费用说明靠近按钮，Header 不遮挡主操作。
3. 未登录可看示例和本地预览；登录后文件及选区保留，停在确认流程。
4. 文件选择、取消选择、拖入、打开示例和切换对比均不创建付费处理。
5. 无效或多文件输入有具体就地提示，能直接重选；视频兼容性未查清时不会提前确认可处理。
6. 演示媒体、真实用户结果和概念稿有清楚标识；初始状态不出现伪造进度、任务或保证。
7. 文件有效后进入本文第 5、6 节的工作区；返回、更换文件与继续任务的行为一致。
8. 后续实现需同步 Astro 内容、CMS 字段/数据、渲染和定向测试；功能状态由服务配置决定，不能仅靠 CMS 修改成已开放。

## 5. 图片工作区

| 状态 | 用户能看到与操作的内容 | 转移条件 |
| --- | --- | --- |
| 空白 | 上传按钮、拖放/粘贴说明、支持格式与 10MB 限制、示例入口 | 选择一个有效文件 |

| 登录/上传/检查 | 保留本地文件与模式；上传百分比、服务端文件检查分开显示；此阶段不启动供应商处理 | 文件完整且服务端检查通过 |
| 待确认 | 模式、具体本站费用、预计输出尺寸/格式；按钮“开始去水印 · X 额度” | 登录与余额通过、报价有效；用户明确点击 |

| 可检查 | 原图/结果/对比切换；可拖动比较，也有不依赖拖动的按钮；适应画布/100%/缩放 | 下载，或进入普通模式的精修 |
| 精修编辑 | 蓝色半透明填充和边界；画笔、橡皮、矩形选区、笔刷大小、撤销/重做/清空、显示选区；当前成功版本始终可下载 | 非空选区后点击“应用精修 · X 额度” |
| 精修处理中 | 保留旧结果，冻结本次提交的选区快照 | 成功生成新版本；失败回到原编辑状态 |
| 可下载 | 实际格式、尺寸、文件大小、可用期限；下载当前成功版本 | 续签链接或文件到期 |

普通自动、PRO 自动、每次精修是三个独立计费操作。工具栏操作、缩放、比较、下载都不收费。精修只在对应会话、遮罩契约和尺寸测试通过后开放；PRO 精修衔接尚未确认，不能默认开放。图片供应商接口本身同步返回结果，不具备文档化的远程任务查询；后台继续与刷新恢复依赖本站持久任务执行，不能用浏览器内存状态替代。

版本记录保存源文件、父版本、模式、选区、实际尺寸、费用和结果。新版本不能覆盖上一成功文件；精修失败仍可下载旧版本。若精修降低分辨率，应在提交前显示具体变化并允许返回高清版本，不能仅在下载后告知。

## 6. 视频工作区

| 状态 | 用户能看到与操作的内容 | 转移条件 |
| --- | --- | --- |
| 空白/本地检查 | MP4、24fps、最长 9 分钟；本地播放和文件信息；真实体积上限核实后再显示 | 本地基础检查通过 |
| 区域设置 | 自动检测 / 固定区域；固定区域为与原视频同坐标的选区；可拖动、缩放和移除 | 完成范围选择 |
| 检查整段 | 暂停/播放、拖动时间轴、检查开头中间结尾；说明“固定区域，对整段生效” | 用户确认区域覆盖目标 |
| 登录/本站上传/检查 | 保留视频与选区；向本站私有 R2 上传并展示上传进度 | 服务端确认编码、帧率、实际时长和文件完整性 |
| 费用确认 | 实际时长、处理范围、具体本站费用、处理后扣费规则；按钮“开始处理 · X 额度” | 登录和余额通过，报价有效且明确提交 |
| 准备处理/向供应商上传 | 预留本站额度；申请并持久保存 task_id；完整传输至供应商，可用时显示传输进度 | 供应商文件上传完成；失败则不进入开始处理步骤 |
| 正在提交 | 使用已有 task_id 开始处理；防止重复提交 | 已接受，或进入状态确认 |
| 处理中 | 仅使用供应商可用的真实进度；提示可离开并稍后返回 | 供应商完成 |
| 正在保存结果 | 已处理，正在取回并保存；此时下载按钮不可用 | 结果完整、可播放、已存私有 R2 |
| 可对比/下载 | 桌面同步播放原片与结果，共用时间轴；手机切换原片/结果并保留时间；显示实际导出属性和期限 | 下载或发起另一次有报价的处理 |

固定区域不随水印移动。水印跳位置时，提示自动检测的效果需验证或更换素材，不提供伪装成跟踪能力的关键帧按钮。首期不提供剪短后免费试片，也不将网页产品的试片功能当作 API 功能。

供应商没有公开取消接口。已提交后只提供“返回工作区 / 稍后查看”；用户可以在提交前放弃上传。不能提供“取消并退款”。

按文档预算，30 秒约消耗 15、60 秒约 30、9 分钟约 270 个供应商积分；这不是本站售价，也不是对最终取整方式的承诺。视频首期必须先确定本站额度与供应商成本的映射，再启用处理按钮。

## 7. 状态恢复与费用规则

主流程：本地检查与设置 → 登录 → 本站上传与检查 → 待费用确认 → 准备处理（视频向供应商上传）→ 正在提交 → 处理中 → 正在保存结果 → 可下载 → 已到期。余额不足和待供应商开放属于前置状态，不应伪装成失败任务。

| 异常 | 界面反馈 | 正确恢复方式 |
| --- | --- | --- |
| 不支持或超限 | 说明实际格式、时长或帧率与允许值 | 更换文件，不调用付费接口 |
| 登录中断 | 文件和设置仍在，提示重新登录 | 回到确认页，不自动收费 |
| 上传失败 | “上传中断，尚未开始处理” | 重试上传，不创建第二个处理操作 |
| 提交超时/断网 | “连接中断，正在确认处理状态” | 查询同一本站操作；视频进一步查供应商 task_id；不能直接创建新任务或立即确认退款 |
| 长时间未完成 | 显示最后同步时间和“检查状态” | 持续对账；本站等待超时不等于供应商已失败 |
| 供应商失败 | 失败原因与本站额度退回状态分开显示 | 退回确认后显示“已退回”；重新处理须再次确认 |
| 结果入库失败 | “处理已完成，正在恢复结果” | 重新取回原结果，不重新去水印 |
| 精修失败 | 旧版本和选区仍在 | 用户可重试新的明确操作，或下载旧版本 |
| 未发现水印 | 解释供应商检测结果，允许检查实际输出 | 不承诺免费或自动退费，先确认供应商计费与本站政策 |
| 下载链接过期 | “正在更新下载链接” | 归属校验后续签，不重新处理 |
| 文件真正到期 | “文件已到保存期限，请重新上传” | 不把已删除文件显示成仍可下载 |

费用不变量：同一个操作只预留一次，成功只结算一次，失败只退回一次。刷新、多标签页、重复点击和登录回调不能重复扣本站额度。供应商未提供幂等契约，因此提交响应丢失时必须进入待确认，不能以自动重发保证恢复。图片仅能查询本站记录；若供应商调用结果未知且本站未保存响应，需保持待确认并对账，不能承诺远程轮询或自动恢复结果。

供应商积分和本站额度独立记账。供应商退款尚未到账时，不能显示本站用户已收到退款；若本站决定先行退回，须有可追踪账本。免费次数的发放上限不能吞掉已预留额度的退回，预留金额和可领取奖励需分开处理。

任务列表只显示属于当前账号的短期任务。每行包括文件名/缩略图、图片或视频、状态、已确认费用、剩余保存时间和继续入口；不是无限期云盘。退出账号后清除本地私有预览；重新登录只能恢复本账号任务。

## 8. 文件、隐私与跨平台实现约束

原文件、选区、每个成功版本和任务状态均进入私有 R2，浏览器只拿短期授权地址。供应商 Key 只在服务端使用；供应商视频存储只作为处理传输环节，不能替代本站私有结果存储。日志不保存密钥、完整签名地址或用户媒体。

本站计划保持临时文件约 24 小时策略，并在结果页显示实际截止时间。上传、任务状态和结果的期限分开计算；处理中任务不能被普通生命周期提前删除。供应商下载地址有效 2 天，不代表本站提供两天文件保管。删除本站文件也不能宣称供应商已同步删除。

高清原件与精修版本分开。JPG / MP4 为实际验证后的下载格式；文件名建议为原名加 `-cleaned` 或版本号。视频音轨、时长、分辨率和编码必须检查实际结果再展示，不写“保证无损”。

后续实现保持 Astro 静态内容 + React 交互岛；图片与视频处理继续通过 Provider 契约隔离。媒体检查、可选转码和后台任务使用跨平台运行方案，不依赖 Windows、PowerShell 或固定盘符。当前文件路径只用于本次工作区取证，不属于产品实现。

## 9. 桌面、移动与可访问性

沿用现有蓝白视觉、深色文字、Plus Jakarta Sans 标题和 DM Sans 正文。视觉变化集中在工作区结构，不重做整站品牌。图稿中的媒体和费用均为概念，不作真实处理宣传。

桌面把画布作为主区域；精修工具与结果版本靠近画布。视频使用共享播放位置的原片/结果对比，避免两个播放器时间不一致。

手机采用全宽画布、底部工具条和固定主操作区，避免桌面侧栏挤压内容。选区/移动模式明确切换；双指缩放不能误画选区。视频用原片/结果按钮切换，不把两幅画面压成小窗。

触控目标至少 44px；当前工具提供文字与选中状态。选区同时有半透明填充和边界，可隐藏检查。对比不强迫拖滑块；矩形选区可用键盘调整。进度状态向辅助技术播报，焦点在弹窗关闭后返回原控件。

## 10. 验收与真实功能验证计划

本轮完成的是文档与源码调研、交互定义和概念稿，未测试 API 输出质量、实际成本、视频耗时和稳定性。浏览器未获授权打开供应商页面，因此也没有完成线上演示走查。现有站点的两张截图用于视觉生成，属于历史截图，不是本轮浏览器验收。

### 产品验收

1. 登录前选择文件和选区，登录后全部保留，停在确认页，未触发处理。
2. 连续点击、刷新、回调和多标签页均只保留一个操作与一次额度预留。
3. 透明图转 JPG 的白色背景、6000px 图片上限、1920px 精修上限均在付费提交前可知；首期超限先拒绝并说明如何准备文件，不静默改变尺寸。
4. 普通图片可对比、放大、精修、下载；精修失败仍保留上一成功版本。
5. 视频限制在付费调用前由服务端核实；固定区域在时间轴检查时保持同一位置。
6. 视频提交断网后查询原任务；结果入库失败只恢复结果，不再次调用处理。
7. 完成任务的实际结果可以下载、重新打开；下载链接过期可续签，文件到期有明确提示。
8. 原片/结果播放时间同步；手机切换画面不丢失播放位置；音轨和实际输出信息可核对。
9. 失败和退款状态可追踪；无水印、精修和重做有明确费用语义。
10. 跨账号无法读取其他人的文件、选区、任务、会话和结果。

### API 小样验证

使用有权处理的自有图片和视频，覆盖角标、平铺文字、半透明水印、复杂纹理、商品文字保护，以及固定与移动水印、音轨和可变帧率。先验证普通图片、一次精修、PRO 和一个短 MP4 的完整链路，记录输入/输出尺寸、文件格式、音轨、耗时、账户扣费、失败语义和肉眼质量。精修遮罩协议须先用最小样本确认，再扩展测试。

举例：普通 1 次 + 精修 1 次 + PRO 1 次 + 10 秒视频，按当前文档约为 10 个供应商积分。该数值仅作最小样本预算，不是已执行测试或消费授权；失败边界应优先用本地契约测试覆盖，避免循环消耗采购额度。

后续实现行为变化先定向红测再最小实现，覆盖操作级浏览器场景；API、鉴权、R2 和 Provider 范围适用本地 release:verify。只有进入发布阶段才执行 CI、部署和对应一次真实功能烟测；定时烟测继续保持公开只读。
