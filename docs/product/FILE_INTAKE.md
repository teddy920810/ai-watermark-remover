# Shared file intake

Status: current implementation contract. PR98 deployment and real operation acceptance are recorded in the [refactor ledger](./REFACTOR_LEDGER.md); the later video-entry delivery is recorded in [release records](./RELEASE_READINESS.md). Local fixtures and production evidence remain separate, and later changes require their own applicable verification.

Public pages prepare files locally and hand them to the same App. The homepage, all published tool pages, upload actions in their copy, and the site conversion banner use `MediaLauncher`. Its button is always **Upload file** and its picker/drop target accepts supported JPG, PNG, WebP and MP4 files. The file determines media type; visitors do not choose an Image/Video mode first. Audio and other containers are rejected locally.

Picker placements share one bounded public capability-guide request per document; a failed request can be retried by a later placement. This does not cache balances, prices, task state or server admission decisions. Tool pages put the picker before the example preview on mobile so the primary action remains discoverable.

Exception: `/gemini-watermark-remover` uses the same automatic file identification but hands its primary/footer picks to `/app/free/gemini`, without a cloud capability gate or media upload. Its free local image/video operations and explicit original-file handoff back to the paid workspace are documented in [FREE_GEMINI.md](FREE_GEMINI.md). Other public recommendations retain the durable workflow below.

`identifyLauncherMedia` owns byte-signature/MIME checks and media-specific admission limits. `media-drafts` owns the temporary IndexedDB handoff, expiry and owner isolation. App pickers and drops use these same primitives; durable operations retain their extra decode/preflight checks before replacing a valid source. Selecting a file does not create a processing task or spend credits. Anonymous intake does not upload it. An authenticated App may prepare/check a private file under its existing rules; processing still needs the appropriate explicit action and accepted price.

The page's existing tool type supplies an optional recommendation. A Coming Soon label supplies an unavailable hint. These hints travel with the local draft; they do not enable a Provider or choose a price. A saved task and explicit operation selection take priority. An incompatible file opens a compatible workspace with an explanation. An unavailable source produces a notice and offers the existing supported operations. Server capabilities, ownership and quotes remain authoritative.

Without a file or draft, the video page's **Open workspace** link and file-error recovery link open `/app/video`. Other pages keep the existing `/app` recovery entry. Choosing a file still takes priority over that page recommendation: a supported image opens the image workspace, and an MP4 opens the video workspace.

`AppShell` owns the App drop surface and ignores replacement drops while the current operation is locked. The durable coordinator owns preparation for all six operations. Object selection retains its separate brush/lasso/eraser/history policy. Background review retains transparent/color PNG. Background/object paste uses the same file checks and ignores text fields or locked tasks. While a local replacement is being identified, confirmation is disabled; invalid bytes leave the checked original and its selection intact. A late local file read must not navigate or replace the editor after the operation starts. Current jobs and accepted quotes continue using their original identity.

App purchase recovery links retain the current operation/task query and hash. Existing public return paths remain accepted. Buying credits opens a separate tab and does not discard the current source or resubmit processing automatically.

CMS owns public titles, descriptions, steps, FAQs, images, ordering, links and the existing recommendation type/status. Upload action labels, accepted media, admission, processing buttons, capabilities and fees are code-owned. Old uploader-copy fieldsets, their unused component definition and unused footer CTA button/link controls are removed from CMS forms. Content headings/descriptions and genuine navigation links remain editable. Global merge-on-save and compatibility schemas preserve stored fields; App no longer serializes that old control copy.

Public marketing images use [ImageDisplay](./IMAGE_DISPLAY.md): one image is static; a genuine independent Before/After pair may show the shared comparison. On 2026-11-01 the user revoked all 53 P5 replacement mappings: original image references, alt and the homepage example note are restored against 574ad43. The [manifest](./CONTENT_MEDIA_MIGRATION.json) records operator/SEO pending asset review. Engineering owns display mechanics and cannot change content without explicit authorization. No Before source was invented and no bitmap was edited; baked controls remain original pixels, while the already missing original asset keeps normal fallback.

Local verification covers every published primary entry, footer selection, incompatible/unavailable recommendations, App pick/drop, accepted-task replacement races, separate credit balances and unchanged operation-level output/recovery tests. Browser fixtures simulate sessions and Providers; authenticated production validation is a separate gate tied to the deployed version and authorized budget, as recorded in the release evidence.
