# 功能型工具交付标准

功能型工具不能按 SEO 页面验收。页面可访问、标题正确、布局接近参考图，只能证明入口存在；交付完成必须证明用户从输入到可用产物的闭环。

## P0 功能合同

每个工具在开发前填写 `docs/templates/functional-tool-contract.example.json`，至少锁定：

1. **输入**：支持格式、尺寸、拖拽/选择/粘贴及非法输入。
2. **操作**：API 必须显式传递 operation，不能依赖服务端默认值。
3. **状态机**：初始、上传后展开、处理中、完成、失败、重试、重新处理。
4. **产物语义**：不能只断言 HTTP 200；应解码文件并验证格式、尺寸、透明度或指定背景色。
5. **额度合同**：成功任务只扣一次；预览、切换、下载、刷新签名链接不重复扣费；失败遵循明确退款规则。
6. **生产信号**：真实登录、真实 Provider、真实私有存储、真实下载，以及处理前后额度差值。

## 最小测试矩阵

| 层级 | 必须证明 |
|---|---|
| 单元/集成 | operation 路由、Provider 返回、PNG 语义、额度原子性、失败/退款 |
| 浏览器 E2E | 上传后布局、默认结果、原图切换、透明和彩色下载、无二次扣费、错误恢复 |
| Production public smoke | 域名、静态入口、匿名保护；不消耗 Provider 额度 |
| Production functional smoke | 登录、上传、指定 operation、处理、结果/下载语义、额度恰好减一 |

## 完成定义

- 行为改动有红测、最小实现和定向绿测证据。
- PR CI 通过，合并提交已进入 `main`，Production 部署绑定该提交。
- 对涉及真实链路的工具完成一次受控 Canary；缺少登录凭据时必须阻断并报告，不能以 `skipped` 充当通过。
- 不在日志中输出 Cookie、用户资料、对象 Key、签名 URL 或 Provider 凭据。
- 每次线上事故都补为自动化回归：先记录用户可见症状，再锁定根因层和最小防线。

## 新功能复用流程

复制合同模板 → 填写 operation/产物/额度 → 先写红测 → 实现 React island 与服务端接口 → 跑定向绿测及风险门禁 → 手工触发一次功能冒烟 → 保存脱敏证据。定时任务只运行无成本 public smoke，避免自动消耗 Provider 额度。
